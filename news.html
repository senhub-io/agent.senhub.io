0.6.4
2026-10-18
LatestBreakingNew

The network on the map, and Kubernetes from the node

The agent now draws the network it sits on: routing tables, SNMP discovery over LLDP, and the machines it finds along the way. It also renames the series that say whether a service is running, so read the first half of this entry before upgrading a fleet.

Before you upgrade
  • Service state is one series on both systems. host.service.running replaces systemd.unit.active_state and windows.service.state, keyed the same way on Linux and Windows. An alert or a panel still reading an old name returns nothing at all. detail: full keeps the old families.
  • systemd and winservices watch fewer services. With no list configured they watch what the supervisor starts by itself, enabled units and automatic services, instead of every unit. A configuration that names its own keeps them.
  • Both probes are now added by default, as probes.d/05-services.yaml, with a Swarm probe where a Docker socket exists. Renaming a file to *.disabled is the supported opt-out, and SENHUB_DEFAULT_PROBES=off stops the agent adding either.
  • PRTG sensors built on these probes change. A winservices or systemd sensor keeps one channel per watched service and gains a Check Result channel; the per-service Status channels go, along with the services the supervisor does not start by itself. A Windows cpu sensor loses its per-core detail channels and gains two Host Clock channels. PRTG keeps the channels the agent stops sending, without data: delete them from the sensor, or delete the sensor and add it again. Memory, network and disk sensors are unchanged.
  • The agent version leaves the metrics. service_version and otel_scope_version disappear from every series, which a Prometheus-like backend recreates once on upgrade. The version stays on logs, traces and senhub.agent.build.info.
  • Leaner host defaults, each restorable. The network probe drops container and virtualisation interfaces and the ip label; on Windows the cpu probe drops the per-core detail. Each one comes back with its option.
  • SNMP topology is swept every minute instead of every ten, so a link that goes down is on the map within the minute and polled devices answer a few more walks. Devices no longer carry mgmt.ip; their addresses are entities.
  • SENHUB_HOST_ID is read by the agent itself, where only the container entrypoint used to read it. A host that sets it outside the official image changes identity on upgrade; an invalid value is logged and ignored.
New
  • SNMP discovery maps the network from the agent's host. From its seeds, or from the host's own default gateways, it follows LLDP neighbours inside the host's private networks and puts every device it finds on the map with its interfaces, addresses, routes and links. A profile with the community is enough to start.
  • Full routing tables. Hosts and SNMP devices publish every route with its type, its origin in the IANA vocabulary, its egress interface and its metric, each next hop of a multipath route on its own. Capped at 500, with senhub.routes.omitted saying how many were left out.
  • Kubernetes from the node. Each node becomes a k8s.node entity joined to the host it runs on; the DaemonSet reads kubelet CPU, memory, filesystem and network for the node, its pods and their containers, and follows pod logs from /var/log/pods. Two Grafana dashboards ship with it.
  • Every probe says what it checks, and why a check failed. Each series carries the identity of the entity it describes, and senhub.probe.check.result tells a target that is down from a check that could not run: refused credentials, timeout, TLS error, configuration error, unreadable reply, missing permission.
  • Windows events carry their message. windows_eventlog sends what Windows renders, not only the provider, the event id and the insertion strings. A low-virtual-memory warning now names the processes that consumed it.
  • Also: Redis Sentinel and ACL support, host clock synchronisation, severity derived from nginx and Apache status codes and from more log formats, an opt-in rail for the agent's own warnings, and series metering for Enterprise.

0.6.3
2026-10-13
New

The Azure Container Apps collector, finished

  • Discovery that reports its own coverage. Every application of a subscription is found and followed, and the probe publishes how many it found, followed and left out — so "26 of 26" is a metric, not a hope.
  • Container App Jobs are discovered too, each with its own execution history, and one Azure identity is shared by every Azure probe instead of being repeated per probe.
  • senhub-agent check azure — a read-only command that verifies the token, the subscription, what is visible and each permission, before anything is deployed.
  • Log volume per application, counted in bytes of published bodies, so it compares with what Log Analytics bills. Plus two official Grafana dashboards.
  • Configuration, secrets and identity on an Azure Files share, and the on-disk queue carried a three-hour backend outage with no log lost.

0.6.2
2026-10-08
SecurityBreakingNew

Linux packages, fleet deployment, and a credential leak closed

  • Signed Linux packages and repositories, plus three ways to deploy at scale: an Ansible collection, a Helm chart and a Podman Quadlet unit. Probes can also be declared from environment variables.
  • Security — act on this one. A credential embedded in a probe's connection URI (scheme://user:password@host: MongoDB, Redis, PostgreSQL, AMQP) was written in clear to the agent log in 0.6.1 and earlier. 0.6.2 masks it. If you used such URIs: upgrade, delete or rotate the old log files, and change that account's password.
  • Breaking: a host's name is now one value everywhere — a host.name override that only reached metrics and logs now also names the host entity and its systemd units. The host.id is unchanged, so the topology node is the same node.
  • Lighter at rest. Probe definitions and console pages are parsed when first needed rather than all at start, and five lines that fired on every healthy cycle moved from INFO to DEBUG.

0.6.1
2026-09-30
BreakingFixed

Metric names and units follow the conventions

A corrective release, but one that renames series. promtool check metrics flagged 0.6.0: some were exported in milliseconds, microseconds, hours or bits per second, where both the Prometheus and the OpenTelemetry rules ask for seconds and bytes.

  • Durations are now in seconds, throughputs in bytes per second, and a list of gauges loses its .total suffix. Dashboards, alerts and recording rules on the old names need updating — the note carries the full table.
  • Zabbix item keys follow the metric names. Re-run zabbix setup to refresh the templates; items under the old keys stop receiving data and keep their history.
  • The Zabbix server is set at install time — ZABBIX_SERVER for the MSI, --zabbix-server for config init, an environment variable for the container. A new host registers and fills in by itself.
  • Topology. A route is identified by its destination and its next hop, interfaces carry their subnets and addresses, Windows hosts publish their routes, and SNMP devices no longer flicker.
  • The console reports measured values. Resident memory and CPU are now the real figures, with the Go heap shown beside them.
  • Watch out on Linux: senhub-agent update run by 0.6.0 installs the new binary without restarting the service — finish with sudo systemctl restart senhub-agent.

0.6.0
2026-09-29
NewBreaking

Native Zabbix, a separate administration key, and entities by default

The largest release so far. Read the upgrade list before you take it: ten points, and two of them change data you may already be querying.

  • Zabbix, both directions. An active agent that registers itself and pushes on :10051, a passive one that answers polls on :10050, TLS and pre-shared keys, and templates generated from the probe definitions — imported for you by senhub-agent zabbix setup. Zabbix 6.0, 7.0 and 8.0.
  • A separate administration key. The console and the configuration API no longer answer to the agent key. A bookmarked console address now returns 401 — open it with senhub-agent console, or get the address with console --print.
  • Entities by default in the container, the agent shows its instance id (senhub-agent key instance-id), and logs and traces from the machine carry its host identity. config check now warns when an OTLP output would send no entity event at all.
  • Probes. The counters a native Zabbix agent reports, on Linux and Windows. A new probe for Azure Container Apps jobs. The Veeam probe now says which protected objects get no job status. And every probe page lists every metric it produces.
  • Watch out: service.instance.id becomes a UUID and changes once — series keyed on it restart. An unfiltered process probe keeps only its per-name roll-up. A Nagios value equal to the threshold is now OK. ActiveMQ and Redfish metrics are renamed, and SNMP interface series move to network_interface_name.

0.5.5

NewBreaking

A console on the box, and an official container image

  • Rebuilt web console. A Probes page with an editor and a Test button, a Settings page for port, bind address and licence.

0.5.0
2026-07-06
NewSecurity

Secrets leave the configuration file

  • Secret store. ${secret:NAME} references resolve at config load time, so passwords and tokens never sit in plaintext on disk.
  • OS-native backends chosen per platform: age-keyfile on Linux, systemd-creds as the hardened option.
  • CLI. agent secret set/get/list/rm/status — a value is never accepted as a command-line argument.
  • Migration. config_version 3 seals inline plaintext secrets into the store on boot and rewrites the file.
