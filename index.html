OpenTelemetry-native agent for hosts and infrastructure.

One agent to feed them all.

Free and Apache-2.0. Collects host, network, container and vendor metrics once, models them on OpenTelemetry semantic conventions, and serves them natively to the platforms you already run.

  • OpenTelemetry
  • Prometheus
  • Zabbix
  • PRTG
  • Nagios

Over OTLP, also Elastic, Graylog, Datadog, Dynatrace and other backends that take OpenTelemetry.

Install Source on GitHub
Point it at a collector
$ senhub-agent config init --otlp-endpoint otel-collector.internal:4317
Then add a probe, one file per probe
# /etc/senhub-agent/probes.d/10-postgresql.yaml
- name: postgresql
  type: postgresql
  params:
    host: db.example.com
    port: 5432
    username: senhub_monitor
    password: ${secret:postgres.password}

PRTG, Nagios and Prometheus need no configuration at all: they are served from the built-in HTTP output. Secrets are stored with senhub-agent secret set, read from standard input, never from the command line.

Zabbix support

The agent works with Zabbix in both directions. In active mode it connects out to the server on port 10051, asks which items it should collect for this host, and pushes values in batches. Encryption uses a pre-shared key or a certificate. Unknown hosts trigger autoregistration, so a new machine appears in Zabbix without manual setup. Proxy groups are followed to the member holding the host.

In passive mode the agent listens on port 10050 and answers polls from the server. TLS is used with an allow-list of permitted addresses. It accepts both the raw key format used before Zabbix 7.0 and the framed request introduced in 7.0. Plaintext polls, wrong keys, or wrong identities are refused.

Templates are generated from the agent's own probe definitions, one per probe type and platform. Low-level discovery handles filesystems, interfaces, and instances that vary in count. Host inventory fields are filled from what the agent knows about the machine, keeping the Zabbix side from drifting. The setup command imports templates, creates the host group, and creates the autoregistration action: senhub-agent zabbix setup --url <frontend> --token-file <f>.

Autoregistration in Zabbix only supports a pre-shared key for encryption, not a certificate. SenHub Agent uses that key, so a fleet can enrol itself where that step is encrypted. Verified against Zabbix 7.0 and 8.0. PRTG and Nagios are served natively from the same process.

Resource attributes

Owner, criticality, site and lifecycle are declared once in the agent's configuration and ride with every metric and log the agent emits. They are OpenTelemetry resource attributes, so they survive the trip into any backend that understands them. Hosts, containers and services carry them into the entity graph, where you can filter on them. 

# senhub-agent.yaml
resource:
  entity.owner.team:      platform-core
  entity.owner.contact:   platform@example.com
  service.criticality:    critical
  entity.location.site:   par-dc1
  entity.lifecycle.status: production

The same attributes are included on every output, so when an alert fires the owning team, contact, and criticality are already in the signal.

One binary

A single static Go binary: no JVM, no Python, no agent framework, nothing extra to keep patched. Linux amd64 and arm64, Windows amd64, signed packages, an MSI installer and an official container image. It runs on bare metal, a virtual machine, a container or a Windows server, collecting locally and serving out from the same process.

It also carries its own console: edit a probe and test it in place, set the listen port, the bind address and the licence, without touching a file.

What's new

Each release note explains what changed and what breaks.

0.7.1current

OpAMP remote management and parallel probes

0.7.1 replaces the unreleased 0.7.0 and fixes masking of configuration sent to a management server. The agent supports OpAMP Enterprise management with signed overlays, parallel probes with collect_timeout. The first PRTG or Nagios reading after a start waits for data.

0.6.5

Secrets masked in log records

Log records are masked before leaving the agent, so clear passwords and tokens never reach the backend. The Proxmox VE probe now covers disk, ZFS, and backup health, and the console has a page per probe.

0.6.4

SNMP discovery and Kubernetes from the node

The agent maps its network using routing tables, SNMP discovery over LLDP, and discovered machines. Kubernetes nodes report kubelet metrics and pod logs, and the series indicating service status are renamed.

Entities and relations

Collecting a metric means identifying what produced it. So alongside the measurements, the agent can emit the things themselves as OpenTelemetry entity events: hosts, services, containers, network interfaces and the relations between them.

That output feeds Toise, our map of what runs where and how it changed. It requires an OTLP output; an agent deployed only for Zabbix, PRTG or Nagios collects metrics and stops there.

This is the newest part of the agent and it is still early work. It comes with a collection you were running anyway.

Open core

The agent, every output, and 65 of the 83 integrations are Apache-2.0. No output and no protocol is behind a licence.

The 18 vendor integrations that required weeks of protocol work are the commercial layer: Citrix, NetScaler, Veeam, VMware HA, Oracle Enterprise, PowerStore, the Azure and Microsoft 365 ones.
