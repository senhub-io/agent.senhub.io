Free and Apache-2.0. Collected once on your hosts, served at the same time to OpenTelemetry, Prometheus, Zabbix, PRTG, Nagios and the other platforms below.

Zabbix, both directions

Active on port 10051 with autoregistration, passive on 10050 with TLS. Templates and low-level discovery are generated from the probes, and senhub-agent zabbix setup imports them. Verified against Zabbix 7.0 and 8.0.

PRTG and Nagios, no setup

Served natively from the built-in HTTP output, next to the Prometheus endpoint, by the same process that collects.

Learn more →

OpenTelemetry first

Metrics, logs and traces over OTLP, modelled on OpenTelemetry semantic conventions, to a collector or straight to a backend.

Learn more →

Resource attributes

Owner, criticality, site and lifecycle are declared once and ride with every metric and log, on every output. When an alert fires, the owning team is already in the signal.

Learn more →

One binary, its own console

A static Go binary for Linux amd64 and arm64 and Windows amd64, as signed packages, an MSI and a container image. A local console shows probes, outputs and failures.

Learn more →

Entities and relations

Hosts, services, containers and interfaces, with the relations between them, as OpenTelemetry entity events. The newest part of the agent, still early.

What's new

0.7.1

OpAMP remote management and parallel probes

0.7.1 replaces the unreleased 0.7.0 and fixes masking of configuration sent to a management server. The agent supports OpAMP Enterprise management with signed overlays, parallel probes with collect_timeout. The first PRTG or Nagios reading after a start waits for data.

0.6.5

Secrets masked in log records

Log records are masked before leaving the agent, so clear passwords and tokens never reach the backend. The Proxmox VE probe now covers disk, ZFS, and backup health, and the console has a page per probe.

0.6.4

SNMP discovery and Kubernetes from the node

The agent maps its network using routing tables, SNMP discovery over LLDP, and discovered machines. Kubernetes nodes report kubelet metrics and pod logs, and the series indicating service status are renamed.
