    Next (unreleased)¶

    0.6.4 puts the network on the map from the agent’s host: full routing tables, SNMP discovery, Ethernet aggregates and ARP/NDP neighbours, with Kubernetes resource and pod log collection from a DaemonSet, severity derived from more log formats, Redis Sentinel and ACL support, clock synchronisation reporting, and an opt-in self-log rail. It also fixes identity handling, SNMP series labels, Redis empty databases, heartbeat jitter, export counters, and other issues.

    Before you upgrade¶

    • Leaner host defaults, each restorable. The network probe no longer collects container and virtualisation interfaces (veth, docker, br-, cni, flannel, cali, cilium, vxlan, …; Hyper-V vEthernet adapters are kept) nor the ip label on interface series; include_virtual_interfaces: true and address_label: true restore them. On Windows the cpu probe keeps per-core usage and the full total, and per_core_details: true restores the per-core user, privileged, interrupt and DPC series. The PRTG channels of the dropped series disappear unless the option is set.
    • Kubernetes containers have one producer. On a Kubernetes node the docker probe no longer publishes containers carrying io.kubernetes.pod.uid; the kubernetes cluster probe describes them.
    • SNMP topology is swept every minute by default. topology_interval of snmp_poll (and so the discovery crawl) goes from 10 minutes to 1 minute, so a link going down is on the map within a minute. Polled devices answer a few more SNMP walks per minute; set topology_interval back to 10m on a device that should be queried less often. Devices no longer carry mgmt.ip, which depended on the agent polling them; their addresses are network.address entities.
    • Metric series no longer carry the agent version. service.version is left off the metrics resource and the metric scope carries no version, so service_version and otel_scope_version labels disappear from every series in a Prometheus-like backend. Upgrading to 0.6.4 recreates the series once more; later upgrades no longer do. The version stays on logs, traces and senhub.agent.build.info.
    • SENHUB_HOST_ID is now read by the agent binary itself. Previously only the container entrypoint used it; the agent now honours a valid value directly (lowercase, dashed machine-id). Hosts run outside the official image that set SENHUB_HOST_ID will change identity; an invalid value is logged and ignored.
    • Hosts and SNMP devices now publish full routing tables. Each route appears as an entity with route.type, route.protocol, the egress interface and metric, capped at 500 per host or device; senhub.routes.omitted reports how many were left out. Topology consumers will receive these new entities and attributes.
    • SNMP device and interface metrics are born with their keys. network.device.id and network.interface.name are present from the first data point; previously a series could be emitted without them and later gain labels, creating a keyless orphan series.
    • An empty Redis database now reports db0 at zero. When Redis omits the keyspace line for an empty db, the probe publishes DB 0 Keys, DB 0 Expiring Keys and DB 0 Average TTL at 0 (except on Sentinel). Alerts that relied on the absence of these channels will see them appear.
    • The Redis replication role at -1 now reads “Sentinel or unknown”. It no longer says “Unknown” with a warning on every Sentinel.

    Features¶

    • Kubernetes nodes as their own entity. The kubernetes probe publishes each node as k8s.node (its role in the cluster: kubelet version, runtime, schedulable, Ready and pressure conditions), joined by same_as to the host it runs on, which keeps the machine facts.
    • Select all / Clear in the URL builder. Each tag filter of the console's sensor URL builder starts with "Select all" and "Clear".
    • Kubernetes Grafana dashboards. kubernetes-workloads.json (node, pod and container resources from kubelet_stats) and kubernetes-logs.json (pod logs and their volume) in docs/grafana/.
    • Ethernet aggregates on the map (opt-in). LAG / LACP port-channels on switches and bonds or teams on Linux hosts and hypervisors: each member port is linked to its aggregate, with the aggregate's mode and, where it exists, each member's LACP or active-backup state, so a path no longer stops at an aggregate. entities.aggregation.enabled, off until the receiving Toise registers the relation.
    • Hosts say whether they route. senhub.host.ip_forwarding.ipv4 and .ipv6 on the host entity, so a multi-homed server is not drawn as a gateway.
    • Full routing tables on the map. Hosts and SNMP devices publish every route with its type (connected, remote, reject, blackhole), its origin (static, OSPF, BGP… in the IANA vocabulary), its egress interface and metric; each next hop of a multipath route is its own route, IPv6 included. Connected routes give the last hop of a path. A bound of 500 routes per host or device, with senhub.routes.omitted saying how many were left out. See SNMP Poll → Routes.
    • SNMP discovery maps the network from the agent's host. The discovery block of snmp_poll now runs: from its seeds it follows LLDP neighbours, within bounds, and puts every device found on the map with its interfaces, addresses, routes and links. Without seeds it starts from the host's default gateways, and without allowed_cidrs it stays inside the host's private networks, so a profile with the community is enough. senhub.snmp.discovery.* metrics report devices, runs, duration, failures and seeds.
    • ARP and NDP neighbours on the map (opt-in). Each neighbour in the host table becomes a network.neighbor entity identified by {host.id, mac}, carries its addresses and the interface it was seen on, with a neighbor_of relation to that interface. entities.neighbors.enabled turns it on; entities.neighbors.resolves_to adds a resolves_to edge to the interface that owns the MAC when this agent observed both ends (basis arp, ndp or fdb). Both are off by default: the receiving Toise must know the network.neighbor type, and register resolves_to before that edge is turned on.
    • Kubernetes resource metrics from the kubelet. The Helm DaemonSet enables kubelet_stats by default; the probe reads the kubelet Summary API for CPU, memory, filesystem and network of the node, pods and containers, named after the OTel k8s conventions, with namespace globs to narrow pods. The chart binds the required ClusterRole, mounts the token and passes the node IP; insecureSkipVerify defaults to true because kubelet certificates are often self-signed.
    • Kubernetes pod logs from the DaemonSet. Helm enables podLogs by default, writing a kubernetes_logs probe that follows /var/log/pods on each Linux node. Every pod is discovered (the agent's own excluded), CRI partial chunks are reassembled, offsets survive rotation by inode, and records carry the OTel k8s attributes; include/exclude globs and optional multiline stack-trace folding are available.
    • Host clock synchronisation. The cpu probe reports system.clock.synchronized, estimated and maximum error, and the detected time source on Linux via adjtimex; on Windows it reads the Windows Time Service counters. system_clock_max_error is omitted when the platform cannot provide it instead of reading 0.
    • Redis Sentinel and ACL support. redis adds Sentinel quorum, failover state and peer Sentinels per master, with the master address as a tag, and accepts an optional ACL username (AUTH <user> <password>). The page gains a TLS and Sentinel example and the channels a failover moves.
    • Severity from more log formats. The parser derives severity from HTTP status codes in nginx and Apache access logs (5xx ERROR, 4xx WARN, else INFO), and from klog, abbreviated, java.util.logging, PostgreSQL, MySQL, Apache and JSON level keys; prose without a level stays unclassified.
    • Self-log rail (opt-in). SENHUB_SELF_LOGS=warn or error publishes the agent's own warnings and errors as log records from the senhub-agent producer, with senhub.agent.module and other attributes. Unset, off or any other value sends nothing; a token bucket bounds the volume and published/dropped are self-metrics.
    • Every probe says what it checks and why a check failed. Each series of a database, application or platform probe carries the identity of the entity it describes (db.instance.id, service.instance.id, container.id, k8s.node.uid…), exactly as the entity carries it, so a dashboard can show the health of each service. A new series, senhub.probe.check.result, tells apart a target that is down (1) from a check that could not run: refused credentials (2), timeout (3), TLS error (4), configuration error (5), unreadable reply (6) or missing permission (7). Active checks (http_check, tcp_dial, icmp_check, ntp, dns_latency) now put their targets on the map, with a result per target. Existing PRTG channels are unchanged; a "Check Result" channel is added.
    • Series metering (Enterprise). senhub.agent.series.active, .created and .untracked count, per output and probe, the series the agent exports over OTLP, the figure a time-series backend bills on. See Series metering.

    Fixes¶

    • A cut link leaves the map, and a silent device leaves as unmonitored. snmp_poll no longer reports a link while either of its ports reads down, even when the far switch still lists the neighbour. A device that stops answering is no longer replayed after three topology intervals and leaves with the reason "unmonitored", not as gone; a device answering nothing at all no longer appears under an address-only identity. The local interface of a link whose far end was not read recently carries senhub.link.peer_state (unread, stale, unreachable).
    • A neighbour the ARP cache forgot is not reported as ended. When an ARP or NDP entry ages out, on the host or in a device's tables read over SNMP, its network.neighbor now leaves with the reason "aged_out" instead of "terminated".
    • Router-to-router routes reach the next router. A route whose private next hop is an address the agent sees on a device it polls now carries its next_hop_via, so a path no longer stops at every router.
    • Redis 8 key-size lines are no longer read as databases. Channels such as DB 0_distrib_strings_sizes Keys disappear; only dbN lines of the keyspace make a database.
    • The agent image upgrades its base packages at build time. The 0.6.4 image no longer ships a zlib version with a known CVE that container scanners flag.
    • Entity heartbeats publish on a fixed grid. Unchanged entities are re-published on a shared cadence with tolerance, so a ticker firing a few milliseconds early no longer produces alternating 120 s and 180 s gaps.
    • Export failure counters are declared at zero from the start. senhub.agent.export.send.failed is emitted per strategy and reason at start, so alerts reading it do not go silent after a restart.
    • The 0.5.x install split now completes. The 0.5.x 00-http.yaml template is recognised, so the monolithic agent.yaml split is no longer refused and the legacy notice does not repeat at every start.
    • A log file truncated in place is no longer duplicated. When a file is emptied and refilled past the old offset, the tail restarts once and does not deliver the first lines a second time.
